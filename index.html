Normalization

The database follows 1NF, 2NF, and 3NF to reduce duplicate data and keep information organized.

1NF — First Normal Form

Each field contains only one value and there are no repeating groups.

2NF — Second Normal Form

Non-key information depends on the complete primary key.

3NF — Third Normal Form

Non-key attributes depend only on the primary key. This helps avoid unnecessary duplicate data.

Database SQL Scripts

SQL commands used to create the Fitness Workout Tracker database. 

CREATE TABLE users (
    user_id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE exercises (
    exercise_id SERIAL PRIMARY KEY,
    exercise_name VARCHAR(100) NOT NULL,
    muscle_group VARCHAR(50) NOT NULL,
    equipment_needed VARCHAR(50)
);

CREATE TABLE workout_routines (
    routine_id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,
    routine_name VARCHAR(100) NOT NULL,
    description TEXT,
    FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);

CREATE TABLE routine_exercises (
    routine_exercise_id SERIAL PRIMARY KEY,
    routine_id INT NOT NULL,
    exercise_id INT NOT NULL,
    FOREIGN KEY (routine_id)
        REFERENCES workout_routines(routine_id),
    FOREIGN KEY (exercise_id)
        REFERENCES exercises(exercise_id)
);

CREATE TABLE workout_logs (
    log_id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,
    workout_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    notes TEXT,
    FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);

CREATE TABLE workout_sets (
    set_id SERIAL PRIMARY KEY,
    log_id INT NOT NULL,
    exercise_id INT NOT NULL,
    set_number INT NOT NULL,
    reps INT NOT NULL,
    weight_kg DECIMAL(5,2),
    FOREIGN KEY (log_id)
        REFERENCES workout_logs(log_id),
    FOREIGN KEY (exercise_id)
        REFERENCES exercises(exercise_id)
);

CREATE TABLE user_progress (
    progress_id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,
    weight_kg DECIMAL(5,2),
    body_fat_percentage DECIMAL(4,2),
    recorded_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);

Design Report

1. Scenario

The Fitness Workout Tracker Management System was designed to help users record and manage their workout activities. It stores workout routines, exercises, workout logs, workout sets, and fitness progress in an organized relational database.

2. Database Purpose

The purpose of the database is to organize fitness-related information and make workout records easier to manage and monitor.

3. Database Tables

  • Users
  • Exercises
  • Workout Routines
  • Routine Exercises
  • Workout Logs
  • Workout Sets
  • User Progress

4. Normalization

The database follows First Normal Form, Second Normal Form, and Third Normal Form. This helps reduce duplicate information and keeps the data organized.

5. Relationships

  • One user can have many workout routines.
  • One user can have many workout logs.
  • One workout routine can contain many exercises.
  • One exercise can be included in many routines.
  • One workout log can contain many workout sets.
  • One exercise can appear in many workout sets.
  • One user can have many progress records.

6. Conclusion

The Fitness Workout Tracker database provides a structured way to store and organize workout information. Through normalization and relationships between tables, the system can manage fitness data while reducing unnecessary duplication.
